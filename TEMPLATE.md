# Шаблонізатор дня

Власний рушій (`template.js`), без сторонніх бібліотек. Джерело правди для тексту
шаблону — таблиця `templates` (рядок `name='day'`), не файл на диску. Файл
`config/day-template.md` лишається лише дефолтом для `POST /template/reset` і
насінням для першого запуску сервера.

## Синтаксис (рівно 4 конструкції)

| Конструкція | Що робить |
|---|---|
| `{{ token }}` | Підстановка значення з даних. Невідомий (не з реєстру нижче) токен лишається в тексті як є, і потрапляє в `warnings`. |
| `{? token ?} ... {?/?}` | Блок рендериться, лише якщо `token` непорожній/істинний (порожній рядок, `null`, `undefined`, порожній масив — усе falsy). |
| `{% мікропромпт %}` | Рушій це НЕ рендерить — лишає вербатим для генератора (бота/скрипта), який пізніше підставить сюди згенерований текст. |
| `{# коментар #}` | Вирізається завжди, у вивід (ні md, ні html) не потрапляє. Однорівневий — коментар не може містити всередині ще один `{# #}` чи буквальний `#}`. |

Умовні блоки (`{? ?}`) теж однорівневі — не вкладай один в інший.

## Токени

`GET /schedule-tracker-api/template/tokens` повертає цей самий реєстр з описами
українською (`template.js` → `TEMPLATE_TOKENS`):

`date`, `weekday`, `mode`, `mode_label`, `mode_emoji`, `header_image`, `obligation`,
`tasks`, `rituals`, `schedule`, `meetings`, `magic`, `magic_card`, `magic_fact`,
`magic_prophecy`, `magic_absurd`, `space`, `news`, `joke_diagram`, `spice`, `moon`,
`stats`, `claude_comment`, `image_anchor`.

Особливі:
- `mode_label`/`mode_emoji` рахуються з `mode`, якщо не задані явно в даних.
- `schedule`/`meetings` — масиви `{title, time, real}`; у HTML-рендері справжня
  зустріч отримує `class="ev real"` (суцільна межа), згенерована таска —
  `class="ev gen"` (пунктирна межа) — це пряма вимога візуально відрізняти
  реальний календар від вигаданого рушієм плану.
  Стилі під `.ev.real`/`.ev.gen` (+ `.claude-note`, `.image-anchor`) прошиті в
  `template.js` (`SCHEDULE_CSS`) — `renderHtml()` вставляє один `<style>`-блок на
  початку виводу, `SCHEDULE_CSS` також експортується окремо для фронтенду.
- `claude_comment` можна вставити в будь-яку секцію, обгорнувши у `{? claude_comment ?}...{?/?}`.
- `image_anchor` — рушій сам обирає РІВНО ОДНЕ з усіх входжень у шаблоні (детерміновано
  від `date`) і підставляє туди картинку-плейсхолдер, решту прибирає.

## API

- `GET /schedule-tracker-api/template` — поточний текст шаблону.
- `PUT /schedule-tracker-api/template` (`{md}`) — зберігає новий текст, повертає
  `{ok, warnings, usedTokens}` (рендер проти порожніх даних — щоб побачити явно
  зламані токени одразу, до першого реального плану).
- `GET /schedule-tracker-api/template/tokens` — реєстр токенів з описами.
- `POST /schedule-tracker-api/template/reset` — повертає дефолт із
  `config/day-template.md` (файл на диску, не редагується цим ендпоінтом).
- `POST /schedule-tracker-api/day-plan/:date/render` — рендерить уже збережені
  `data` цього дня поточним шаблоном, нічого не зберігає (превʼю).

## Як редагувати

Найпростіше — читай поточний `GET /template`, редагуй md-текст локально (звичайний
markdown + токени), заливай назад через `PUT /template`, дивись на `warnings`.
Якщо щось зламалось незрозуміло — `POST /template/reset` повертає робочий дефолт.
